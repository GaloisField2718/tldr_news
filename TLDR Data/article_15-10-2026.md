 TURNING OPPORTUNISTIC AI INFERENCE CAPACITY INTO BETTER ADS
RECOMMENDATIONS (16 MINUTE READ) [6]

 Meta uses idle computing capacity to improve ad recommendations by
ranking more ads or routing requests to more powerful models. When
that capacity disappears, the system quickly scales back this extra
work while protecting normal service speed and reliability.

 FROM 2,500 REQUESTS TO 24: REBUILDING STAR HISTORY WITHOUT THE
STARGAZERS (7 MINUTE READ) [7]

 GitHub built a star history API that returns daily counts without
exposing users' identities, cutting React's full history from about
2,500 requests to 24. It reduces database work by filtering stars by
date before counting them, rather than repeatedly processing every
star.

 ZERO-DOWNTIME POSTGRES UPGRADES WITH LOGICAL REPLICATION (25 MINUTE
READ) [8]

 Logical replication offers a practical path to near-zero-downtime
PostgreSQL major upgrades, with live rollback enabled by reverse
replication. A Docker-based demonstration ran old and new clusters in
parallel, freezing writes and waiting for replication to catch up
before cutover. It achieved 181 ms of write interruption during
upgrade and 179 ms during rollback, without data loss.

 CASTLE: TRAINING NATURAL LANGUAGE SEARCH BEFORE THE FIRST REAL QUERY
(6 MINUTE READ) [9]

 Cold-start natural-language search often lacks both real queries and
relevance labels. Airbnb's CASTLE jointly generates synthetic queries
and labels from de-identified booking sessions. Its queries matched
real guest query patterns much better than baselines, and human
reviewers agreed with its relevance labels >90% of the time. Carefully
governed behavioral data can bootstrap search training before
meaningful traffic exists.

 NEED TO KNOW: IMPLEMENTING ROW-LEVEL SECURITY FOR CLAUDE DASHBOARDS
VIA MODEL CONTEXT PROTOCOL (11 MINUTE READ) [10]

 This proof of concept shows how to add row-level security to Claude
Dashboards using an MCP server to authenticate users and query DuckDB
for only the data they can access. Access rules are enforced before
data reaches Claude, allowing the same dashboard to show different
results for each user.

 FOUR POSTGRESQL ARGUMENTS THAT CAME OUT EVEN (2 MINUTE READ) [11]

 PostgreSQL micro-optimization alternatives often don't matter. For
1,000 IDs, IN, ANY, and VALUES joins perform similarly; prefer
parameterized ANY for stable query text. Short text, enums, and
smallints use near-identical storage; mostly-NULL columns are cheap.
Don't blindly rewrite but EXPLAIN on your own data.

 REWINDING THE EXPONENTIAL: HOW WE KEEP HARDWARE USAGE DOWN (9 MINUTE
READ) [12]

 Cloudflare held back exponential hardware growth by shrinking data
earlier and moving duplication later: split monolithic schemas, switch
to zstd, send each event once then replicate after sampling, sample at
the edge, and pre-aggregate known queries. Optimize bytes, not just
compute: prune fields, compress measured workloads, push reductions
upstream, and replicate compacted data.

 SQLBUILD: SAFE REFACTORING FOR WAREHOUSE SQL (GITHUB REPO) [15]

 SQLBuild is an open-source SQL and Python transformation framework
for safely changing warehouses. It checks contracts and lineage before
execution, runs graph-level tests and production diffs, and lets teams
rename incremental models or columns while preserving history and
compatibility views. A local DuckDB playground makes it easy to
evaluate. Snowflake, Postgres, BigQuery, and Databricks adapters are
available.

 PHOENIX (GITHUB REPO) [16]

 Phoenix is a self-hosted, open-source AI observability platform for
tracing, evaluating, and debugging LLM applications. It captures
OpenTelemetry traces; offers retrieval and response evaluations,
versioned datasets, and experiments; and supports prompt testing and
replay. Framework- and provider-agnostic instrumentation makes it
useful for teams that need to diagnose agent behavior and measure
changes before production.

 XERJ (GITHUB REPO) [17]

 XERJ is an Apache-2.0, Elasticsearch-compatible local search engine
that automatically indexes code, logs, PDFs, SQLite, and CSVs into
typed datasets for agent retrieval, incident analysis, and RAG. Its
autoindex workflow avoids schema setup and returns ranked passages
with file and line locations. The project defaults to local operation,
although optional reranking can send text to an external provider.

MISCELLANEOUS

 REDESIGNING SOURCE CONTROL AT ANTHROPIC (17 MINUTE READ) [18]

 Anthropic replaced Git with Scion, an in-house version control system
built in five months, after daily code merges grew from 2,500 to over
30,000. By moving operations to servers and fetching only the files
needed, it reports roughly 100 times faster checkouts and 200 times
lower CPU and memory requirements than its previous Git mirror
infrastructure.

 PARSING JSON AT TENS OF GIGABYTES PER SECOND… IN PYTHON (5 MINUTE
READ) [19]

 Daniel Lemire's benchmark processed 7.6 GB of JSON in about 0.12
seconds using fastsimdjson on free-threaded Python across 64 cores,
reaching roughly 66 GB/s. The speed comes from running threads in
parallel and creating Python objects only for the fields needed, with
data already decompressed in memory.
