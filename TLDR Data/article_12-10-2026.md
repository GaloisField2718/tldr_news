DEEP DIVES

 INSIDE LINKEDIN'S DATA CONTEXT LAYER: CURATING TRUSTWORTHY CONTEXT
FOR HUMANS AND AGENTS (16 MINUTE READ) [7]

 LinkedIn built a shared layer that tells people and AI agents which
datasets to trust, which filters and joins are required, and what each
row means. It combines profiles that an LLM writes from schemas, query
logs, and code with notes that teams write and review in Git like
code. After LinkedIn's analytics agent was connected to it, the share
of acceptable answers in one test rose from 25.9% to 79.5%, and median
time to answer fell from 10.7 to 4.7 minutes.

 APACHE SPARK RESOURCE OPTIMIZATION: LESSONS FROM EIGHT MILLION JOBS A
DAY (7 MINUTE READ) [8]

 Salesforce runs about 8 million Spark jobs a day and found some
workloads left executors idle more than 90% of the time. Sizing
targeted workloads to measured usage reduced weekly compute costs by
31%, while runtime, failures, and retries remained within acceptable
levels.

 FROM ACTIVITY TO INTENT: GENERATING USER JOURNEYS WITH LLMS (14
MINUTE READ) [9]

 Pinterest replaces a fragile keyword-clustering pipeline with a
fine-tuned 4B LLM that converts a user's activity history into ranked,
localized “journeys” (active goals). Teacher-model distillation
makes it affordable at scale. The system improves notification
engagement while applying strict output validation, safety filters,
and feedback loops.

 WHAT DEFINES THE STREAMHOUSE ARCHITECTURE? (11 MINUTE READ) [10]

 Apache Fluss' “Streamhouse” concept proposes one maintained
logical table for streaming, serving, and analytics instead of
separate synchronized systems. The key idea is to unify fresh stream
data and historical lakehouse data behind shared metadata and tiering,
so teams stop rebuilding state in multiple places. This can cut
duplicate ingestion while still allowing specialized caches or
replicas for specific access patterns.

OPINIONS & ADVICE

 CLAUDE DASHBOARDS AND THE SHIFT FROM CHART BUILDER TO CHART SPECIFIER
(14 MINUTE READ) [11]

 Anthropic's new Claude Dashboards beta can build a dashboard without
making a single chart manually. You can trace every number back to its
source, but there is no row-level security, refresh, or audit log yet.
The advice to BI developers: spend less time on tool tricks and more
on data modelling, SQL, and design.

 FIVE POSTGRESQL QUERIES THAT DID MORE WORK THAN I ASKED FOR (4 MINUTE
READ) [12]

 Five PostgreSQL benchmarks show how unnecessary deduplication, CTE
materialization, random sorting, extra column retrieval, and unindexed
expressions can dramatically slow queries, with small SQL changes or a
matching index delivering major speedups.

 YOUR ONTOLOGY RECORDS PERMISSION. IT DOES NOT RESOLVE AUTHORITY (11
MINUTE READ) [13]

 Enterprise agents can enforce permissions yet make bad decisions when
formal records omit the people whose judgment shapes outcomes. The
Authority Resolution Framework separates documented rights, system
permissions, recorded approvals, informal influence, and an agent's
mandate, then treats disagreement among them as a governance signal.
Audit authority gaps before automation turns organizational blind
spots into confident actions.

 LEVIATHAN: DEEP MEMORY FOR AGENTS OVER LARGE DATASETS (GITHUB REPO)
[15]

 Leviathan is a Rust tool that gives AI agents compact, cited search
results from large datasets using SQLite full-text indexing, with
optional persistent memory and CLI, MCP, or remote access.

 I'M NOW CONVINCED SINGLE-NODE DUCKDB IS THE BEST ENGINE AT ANY
REALISTIC SCALE (REDDIT THREAD) [16]

 A Databricks user found that Spark, Trino, and DuckDB all spent most
of their time waiting on S3, with CPUs about 90% idle. After running
four times as many read threads as CPU cores, one DuckDB machine beat
Trino on the same hardware by 1.7 to 2.1 times on 10 TB queries.
Against a Trino cluster with 5 to 13 nodes, it was 2 to 3 times slower
but about half the cost.

 AGENT MODE IN THE DUCKDB CLI (11 MINUTE READ) [17]

 The DuckDB 2.0 command line now detects when an AI agent is using it.
It then switches to compact output, flags cut-off results, stops
runaway queries, and returns errors as JSON. Across 132 TPC-H runs,
agents read back about 60% fewer tokens and still got every answer
right.

 ONTOLOGY‐DRIVEN OBSERVABILITY: BUILDING THE E2E KNOWLEDGE GRAPH AT
NETFLIX SCALE (51 MINUTE VIDEO) [18]

 Netflix is using an ontology-driven knowledge graph to make
observability data, incident chatter, and service topology queryable
as one system. This delivers faster automated triage and root-cause
analysis at large scale, with AI helping turn messy human signals into
structured facts. The key takeaway: better incident response may come
from modeling operational meaning, not just collecting more telemetry.


 POSTGRES RELATION FILES, FILED UNDER BASE/ (7 MINUTE READ) [19]

 Postgres stores each relation as physical files identified by
tablespace, database, and relfilenode, with extra forks and TOAST
files appearing as needed. Logical objects and physical files are
loosely coupled: operations like VACUUM FULL or REINDEX can rewrite
storage and swap relfilenodes while the table's identity stays the
same. Large relations also continue transparently across segmented
files.
