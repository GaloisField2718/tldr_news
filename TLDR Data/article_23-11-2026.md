DEEP DIVES

 BEHIND BOOKING.COM'S AI EVOLUTION: THE UNPOLISHED STORY (40 MINUTE
VIDEO) [7]

 Booking.com's platform story is less about flashy AI than repeated
infrastructure rewrites to remove scaling bottlenecks across data,
experimentation, and serving. The company now runs hundreds of models
and hundreds of billions of daily predictions, but one standout lesson
is operational: lineage plus a delete-first migration strategy let it
retire most legacy workflows before cutover, sharply reducing
migration risk.

 SELF-SERVICE AGENTIC ANALYTICS AT MEWS, PART I: DATA FOUNDATIONS (17
MINUTE READ) [8]

 Nearly 500 Mews employees used AI agents to answer their own data
questions in the first month, bypassing the analyst ticket queue. The
agents use shared metric definitions across tools like Claude, Hex,
and Slack, and flag answers that rely on uncertified data.

 HOW WE SCALED METRICS AGGREGATION BY MOVING DURABLE STATE INTO
STORAGE (10 MINUTE READ) [9]

 At Datadog, recovering aggregation state had become the limiting
factor for scaling metrics processing. The system moved from static
worker ownership to dynamically reassigned RocksDB state backed by
blob storage, to a design where time-series storage reconciles partial
aggregates, late arrivals, and duplicates. Keeping historical state
out of the streaming recovery path lets workers resume at the live
edge, but shifts reconciliation complexity into storage and query
paths.

OPINIONS & ADVICE

 THE DATA ENGINEERING AUTONOMY MOMENT: AGENTS NOW BUILD AND RUN DLT
PIPELINES, AND INGESTION BECOMES A 40X BIGGER MARKET (16 MINUTE READ)
[10]

 AI coding agents can now build, run, and fix dlt data pipelines with
little human input, and Claude Code started 92% of agent-run pipelines
in October. dltHub tracked about 28,000 distinct custom data sources
in use, compared with roughly 700 connectors in a typical catalog.

 WHEN CAN YOU SHIP ON OFFLINE EVALS ALONE? (12 MINUTE READ) [11]

 Teams building AI features want to ship on offline evals alone and
skip slow A/B tests. Spotify shows that works only under strong
assumptions that are hard to verify and can change. Noise also hides
the link: in the worked example, a naive estimate says the eval
explains 24% of online variation, when the true figure is 60%.

 WHEN A LAKEHOUSE FAILS: REBUILDING DATA INTEGRITY AND PIPELINE TRUST
(4 MINUTE READ) [12]

 Two IEEE papers focus on a core data-platform problem: how to make
lakehouse pipelines recover reliably and remain trustworthy under
failure. One emphasizes resilient architecture and replay integrity,
while the other explores metadata-driven, AI-assisted ETL with
self-repair. Automation only works when recovery, governance, and
validation are demonstrably reproducible at scale.

LAUNCHES & TOOLS

 POSTGRESQL 19 RELEASED! (6 MINUTE READ) [13]

 PostgreSQL 19 lets teams reclaim disk space without blocking reads or
writes and gives them more control over query plans. It also makes it
easier to enable logical replication without a restart, read recent
writes from standby servers, and get or create a row in a single
query.

 POSTGRESQL 19: LESS FRICTION, MORE CONTROL (31 MINUTE READ) [14]

 This interactive tour runs each new PostgreSQL 19 feature on a real
Postgres 19 server in a disposable sandbox. It covers IGNORE NULLS,
get-or-create inserts, JSON export, JSONPath transformations, and
range subtraction, plus planner advice and live logical and physical
replication experiments.

 INTRODUCING GRAFANA NOTEBOOKS (5 MINUTE READ) [15]

 Grafana Notebooks bring charts, queries, and findings from Grafana
Assistant into one shareable working document. Instead of collecting
screenshots and query links to explain an incident, an analyst can
show a teammate what supports a conclusion. The document also shows
where an assumption is still being made.

 OPENMETADATA 2.1 MAKES SEMANTIC CONTEXT AN OPEN-SOURCE PLATFORM
CONCERN (5 MINUTE READ) [16]

 OpenMetadata 2.1 turns the open-source catalog into more of a
semantic context layer: it imports metric definitions from warehouses
and BI tools, adds hierarchies and finer-grained lineage, and exposes
an RDF knowledge graph through MCP.

MISCELLANEOUS

 PROJECT CHAPERONE: A RULE-ENFORCING HARNESS FOR PROACTIVE ASSESSMENT
AND PREVENTION OF AI AGENT MISCONDUCT (33 MINUTE READ) [17]

 Project Chaperone is an open-source harness for constraining AI
agents with explicit policy checks before and during execution, rather
than relying on prompts alone. It models data-flow, action, output,
and network rules so risky operations can be blocked while safe
workflows still run. Practical agent safety needs enforceable runtime
boundaries, not just instructions.

 YOUR BIGGEST TENANT RUNS SOMEONE ELSE'S PLAN (9 MINUTE READ) [18]

 Prepared statements can push PostgreSQL toward a generic execution
plan that fits the average tenant but performs badly for outliers. For
example, a large tenant triggered far more work and slower queries
than a custom plan. You should observe multi-tenant skew closely and
consider forcing custom plans or redesigning indexes and query shapes.
